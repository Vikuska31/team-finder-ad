# TeamFinder

Платформа для поиска команды в pet-проекты: пользователи публикуют идеи,
находят единомышленников и откликаются на чужие предложения.
Реализован **вариант 1** — «Избранное» и фильтрация пользователей.

## Стек

Python 3.11, Django 5.2, PostgreSQL 16, Pillow, python-decouple.

## Запуск проекта

1. Клонируйте репозиторий и перейдите в папку проекта:

```bash
git clone https://github.com/Vikuska31/team-finder-ad.git
cd team-finder-ad
```

2. Создайте и активируйте виртуальное окружение:

```bash
python -m venv venv
source venv/bin/activate       # Linux/macOS
venv\Scripts\activate          # Windows
```

3. Установите зависимости:

```bash
pip install -r requirements.txt
```

4. Создайте файл `.env` по образцу `.env_example`:

DJANGO_SECRET_KEY=ваш_секретный_ключ
DJANGO_DEBUG=True

POSTGRES_DB=team_finder
POSTGRES_USER=team_finder
POSTGRES_PASSWORD=team_finder
POSTGRES_HOST=localhost
POSTGRES_PORT=5436


5. Поднимите базу данных:

```bash
docker compose up -d
```

6. Примените миграции и создайте суперпользователя:

```bash
python manage.py migrate
python manage.py createsuperuser
```

7. Запустите сервер:

```bash
python manage.py runserver
```

Сайт: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)
Админ-панель: [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/)

## Структура

| Приложение | Назначение |
| --- | --- |
| `users` | Модель пользователя, регистрация, вход, профиль, фильтрация |
| `projects` | Проекты, участие, избранное |

## Маршруты

| URL | Назначение |
| --- | --- |
| `/` | Редирект на список проектов |
| `/projects/list/` | Главная: все проекты, пагинация по 12 |
| `/projects/<id>/` | Страница проекта |
| `/projects/create-project/` | Создание проекта |
| `/projects/<id>/edit/` | Редактирование проекта |
| `/projects/<id>/complete/` | POST: завершение проекта автором |
| `/projects/<id>/toggle-participate/` | POST: участие или отказ |
| `/projects/<id>/toggle-favorite/` | POST: добавить или убрать из избранного |
| `/projects/favorites/` | Избранные проекты текущего пользователя |
| `/users/list/` | Участники платформы, пагинация по 12, фильтры |
| `/users/<id>/` | Публичный профиль |
| `/users/register/`, `/users/login/`, `/users/logout/` | Регистрация, вход, выход |
| `/users/edit-profile/`, `/users/change-password/` | Профиль и пароль |
| `/admin/` | Админ-панель |

## Фильтрация пользователей (вариант 1)

На странице `/users/list/` авторизованному пользователю доступны четыре
фильтра, значение передаётся параметром `filter`:

| Значение | Критерий |
| --- | --- |
| `owners-of-favorite-projects` | Авторы избранных проектов |
| `owners-of-participating-projects` | Авторы проектов, в которых я участвую |
| `interested-in-my-projects` | Пользователи, которым нравятся мои проекты |
| `participants-of-my-projects` | Участники моих проектов |

## Отступления от задания и их причины

- **Адрес главной страницы.** В ТЗ указан редирект на `/project/list/`,
  но все готовые шаблоны и ссылки в шапке ведут на `/projects/list/`.
  Реализован второй вариант, иначе навигация не работает.
- **Контекст списков.** ТЗ описывает контекст `{"projects": ...}` и
  `{"participants": ...}`. Эти ключи передаются, но шаблоны перебирают
  `page_obj`, поэтому в контекст добавлен и он — без этого страницы пустые.
  Пагинация по 12 записей, как требует описание.
- **Регистрация.** В описании страниц сказано, что после регистрации
  пользователь попадает на страницу входа, а в рекомендациях по реализации —
  что его нужно авторизовать и отправить на главную. Реализован второй
  вариант как более конкретный.
- **Подписи статусов.** В базе статусы хранятся как `open` и `closed`,
  как требует ТЗ и как их проверяют шаблоны. Подписи в выпадающем списке
  русские — «Открыт» и «Закрыт», этого требует описание формы проекта.
- **Телефон.** При регистрации номер не запрашивается, поэтому в модели
  поле допускает `NULL`. Обязательность формата и уникальность
  проверяются в форме редактирования профиля; номер нормализуется
  к виду `+7XXXXXXXXXX`, благодаря чему `89991234567` и `+79991234567`
  считаются одним номером.
- **Сортировка участников.** ТЗ требует порядок «в порядке добавления в
  базу (по id)», поэтому на странице участников применён `order_by("id")`.
- **Контекст страницы участников.** В ТЗ для варианта 1 перечислены ключи
  `active_skill` и «все навыки» — они относятся к варианту 2 и здесь
  неприменимы. Передаётся `active_filter`, который и использует шаблон.
- **Переменная `TASK_VERSION`.** Удалена, папка `templates_var1`
  переименована в `templates`, папки других вариантов удалены.
